# Инструкция по тестированию API в Postman

Коллекция `Porsche_Configurator_API.postman_collection.json` содержит полный набор запросов и автоматизированных тестов для проверки серверной части Porsche Car Configurator (Node.js + Express.js + SQLite).

---

## 1. Запуск сервера перед тестированием

Перед началом тестов убедитесь, что сервер запущен:
```bash
npm start
```
Сервер запустится по адресу `http://localhost:3000`. База данных SQLite (`server/data/configurator.db`) будет автоматически инициализирована и заполнена начальными данными.

---

## 2. Импорт коллекции в Postman

1. Откройте **Postman** (десктоп-клиент или веб-версию).
2. Нажмите кнопку **Import** (в верхнем левом углу).
3. Перетащите файл `postman/Porsche_Configurator_API.postman_collection.json` или нажмите **Choose Files** и выберите его.
4. Коллекция появится в боковой панели под названием:  
   **«Porsche Car Configurator REST API (Node.js + Express + SQLite)»**.

---

## 2.1 Важная настройка прокси в Postman (если получаете 404 на localhost)

Если у вас включен системный прокси / VPN, Postman может перенаправлять запросы к `localhost:3000` на внешний прокси-сервер, из-за чего возвращается `404 Not Found` (HTML `<!DOCTYPE html>`).

**Решение в Postman:**
1. Откройте **Settings** (значок шестерёнки вверху справа) -> вкладка **Proxy**.
2. Отключите тумблер **"Use System Proxy"** (OFF), **ЛИБО**
3. В поле **"Proxy bypass"** добавьте: `localhost, 127.0.0.1`.

---

## 3. Переменные коллекции (Collection Variables)

В коллекции уже настроены переменные по умолчанию:
- `baseUrl`: `http://localhost:3000/api` (базовый URL REST API)
- `authToken`: JWT-токен текущего пользователя (заполняется автоматически скриптом при логине/регистрации)
- `user2Token`: JWT-токен второго пользователя (для проверки изоляции прав и ошибки `403 Forbidden`)
- `porscheCode`: уникальный сгенерированный Porsche Code созданной конфигурации (передается в последующие запросы)
- `orderNumber`: уникальный номер заказа (передается в проверку статусов и переходов жизненного цикла)

---

## 4. Структура запросов и сценарии

Коллекция разбита на 4 логические группы в соответствии с требованиями II этапа:

### 1. Аутентификация (Auth)
- **1.1 Регистрация пользователя (`POST /api/auth/register`)** -> `201 Created`
  - Регистрирует нового водителя с динамическим email и именем. Сохраняет JWT в `authToken`.
- **1.2 Ошибка регистрации - дубликат (`POST /api/auth/register`)** -> `409 Conflict`
  - Проверяет возврат HTTP 409 и понятного сообщения об ошибке при повторной регистрации.
- **1.3 Вход в систему (`POST /api/auth/login`)** -> `200 OK`
  - Вход с предустановленным демо-пользователем (`demo` / `porsche123`).
- **1.4 Ошибка входа - неверный пароль (`POST /api/auth/login`)** -> `401 Unauthorized`
  - Проверяет безопасность при неверных учетных данных.
- **1.5 Профиль текущего пользователя (`GET /api/auth/me`)** -> `200 OK`
  - Защищенный маршрут с проверкой Bearer-токена.
- **1.6 Ошибка доступа без токена (`GET /api/auth/me`)** -> `401 Unauthorized`
  - Проверяет защиту маршрута от неавторизованных запросов.
- **1.7 Регистрация второго пользователя (`POST /api/auth/register`)** -> `201 Created`
  - Создает `User 2` и сохраняет токен в `user2Token` для проверки разграничения прав.

### 2. Каталог и Мониторинг (Catalog & Health)
- **2.1 Проверка состояния сервиса (`GET /api/health`)** -> `200 OK`
  - Возвращает статус, аптайм сервера и время отклика.
- **2.2 Полный каталог моделей, отделок и опций (`GET /api/catalog`)** -> `200 OK`
  - Проверяет наличие всех 6 моделей (**911, 718 Cayman, Taycan, Panamera, Macan, Cayenne**) и всех отделок салона (**Bordeaux Red, Race-Tex Alcantara, Truffle Brown, Black**).

### 3. Конфигурации (Configurations CRUD & Logic)
- **3.1 Создание валидной конфигурации (`POST /api/configurations`)** -> `201 Created`
  - Создает конфигурацию Macan GTS с отделкой Bordeaux Red и премиум-опциями. Вычисляет цену на сервере и генерирует уникальный Porsche Code (например, `PR-MACAN-GTS-XXXXXX`).
- **3.2 Проверка серверной бизнес-логики - конфликт опций (`POST /api/configurations`)** -> `422 Unprocessable Entity`
  - Проверяет правило: опция керамических тормозов PCCB требует колес от 20 дюймов. Сервер отклоняет несовместимый запрос с детализацией конфликта.
- **3.3 Получение конфигурации по Porsche Code (`GET /api/configurations/:code`)** -> `200 OK`
  - Чтение созданной конфигурации из SQLite со всеми выбранными опциями.
- **3.4 Список конфигураций текущего пользователя (`GET /api/configurations?mine=true`)** -> `200 OK`
  - Возвращает только конфигурации, привязанные к учетной записи авторизованного пользователя.
- **3.5 Обновление конфигурации владельцем (`PUT /api/configurations/:code`)** -> `200 OK`
  - Владелец меняет параметры автомобиля (цвет, отделку салона, опции). Сервер пересчитывает итоговую стоимость.
- **3.6 Разграничение прав: попытка изменения чужой конфигурации (`PUT /api/configurations/:code`)** -> `403 Forbidden`
  - Пользователь 2 пытается модифицировать конфигурацию Пользователя 1. Сервер возвращает `403 Forbidden`.
- **3.7 Запрос несуществующей конфигурации (`GET /api/configurations/NON-EXISTENT`)** -> `404 Not Found`
  - Корректная обработка отсутствующих сущностей.

### 4. Заказы и Жизненный цикл (Orders & State Machine)
- **4.1 Оформление заказа на базе конфигурации (`POST /api/orders`)** -> `201 Created`
  - Создает заказ с начальным статусом `pending`. Переводит статус конфигурации в `ordered`. Генерирует уникальный номер заказа (например, `PO-261009-XXXX`).
- **4.2 Список заказов пользователя (`GET /api/orders`)** -> `200 OK`
  - Возвращает историю оформленных заказов.
- **4.3 Детали заказа по номеру (`GET /api/orders/:orderNumber`)** -> `200 OK`
  - Возвращает полную информацию о заказе и автомобиле.
- **4.4 Допустимый переход состояния заказа (`PATCH /api/orders/:orderNumber/status`)** -> `200 OK`
  - Успешный перевод статуса: `pending` -> `confirmed`.
- **4.5 Валидация перехода состояний (`PATCH /api/orders/:orderNumber/status`)** -> `422 Unprocessable Entity`
  - Попытка перескочить напрямую `confirmed` -> `completed` в обход производства (`in_production`). Серверная бизнес-логика блокирует некорректный переход.
- **4.6 Удаление конфигурации владельцем (`DELETE /api/configurations/:code`)** -> `200 OK`
  - Завершение жизненного цикла конфигурации.

---

## 5. Запуск всех тестов в Postman Collection Runner

1. В боковой панели Postman наведите курсор на коллекцию и нажмите кнопку **«...» (Меню) -> Run collection**.
2. Убедитесь, что все 20 запросов отмечены флажками.
3. Нажмите синюю кнопку **«Run Porsche Car Configurator REST API»**.
4. Все тесты выполнятся последовательно с автоматической передачей токенов и Porsche Code между запросами: **100% Passed**.

---

## 6. Запуск через Newman (CLI)

Вы также можете запустить коллекцию из командной строки с помощью утилиты Newman:
```bash
npx newman run postman/Porsche_Configurator_API.postman_collection.json
```
Newman выведет наглядную сводную таблицу всех выполненных запросов, статусов и проверок.
